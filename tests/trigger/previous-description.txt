Ticket board kept as markdown files in a repo's `.kerjaan/` folder; its subfolders (backlog, todo, in_progress, review, done, cancel) are the statuses. Use it to create, move, edit or list tickets, answer what is planned, in flight or in review, start a board, and work the queue through worker and reviewer agents. Where `.kerjaan/` exists, trigger it whenever a request mentions tickets or those statuses, and on indirect asks like "note this down for later", "put that on the backlog", "not now, maybe later", "mark that as done", "what are we working on", "work the queue", "catat ini dulu", "tandai sudah selesai", "apa saja yang sedang dikerjakan", "kerjakan tiket berikutnya". Without `.kerjaan/`, review, done or todo alone mean ordinary code work. Prefer it over an ad-hoc TODO list or notes file.
